# PU 合成性评分器性能与来源审计

本报告是独立审计产物，不修改论文正文或补充信息。审计对象是服务器上的
`clscore_all.csv`（评分器 A）和 `clscore_b_all.csv`（评分器 B）所对应的两个
PU-learning 管线。报告中的 AUC 全部来自保存的逐袋日志；它们是验证集指标，
不是合成失败的真实识别率。

## 结论先行

评分器 A 和 B 使用相同的 50 个 PU bag 划分和相同的 out-of-bag（OOB）掩码，
但编码器和训练头不同，因此可以作为两种结构表示下的互补排序意见：

| 输出标签 | 模型 | 50 袋 best validation ROC-AUC（均值 ± 样本标准差） | 范围 |
|---|---|---:|---:|
| CGCNN-PU OOB | 从头训练的晶体图卷积网络（CGCNN） | 0.976538 ± 0.000763 | 0.9749–0.9781 |
| MatterSim-1M-MLP-PU OOB | 冻结 MatterSim-v1.0.0-1M 表征 + MLP PU head | 0.946561 ± 0.000941 | 0.9443–0.9486 |

这里的验证标签是“实验正结构”对“按该 bag 从未标注池抽取的伪负结构”。
源数据没有观察到的难合成/失败合成负标签，也没有 untouched independent test
文件。因此不能把上表称为 test accuracy、真实可合成性准确率或对失败合成的
召回率。

优化后的 MatterSim 重算（Slurm 209663）还给出了每袋 PR-AUC
`0.938953 ± 0.001369`、阈值 0.5 的 accuracy `0.877183 ± 0.001771`、
balanced accuracy `0.877033 ± 0.001875` 和 F1 `0.871581 ± 0.002296`。
这些量仍然只描述“实验正例 versus 抽样伪负例”的验证任务。

## 两个分数究竟是什么

### A：CGCNN-PU OOB

`03_train_bags.py` 的模型说明给出 CGCNN 的 3 个卷积层、64 维原子特征、128
维晶体特征和二分类头（文件第 2–13 行）；每个 bag 在其验证集上计算 ROC-AUC
并保存当前最佳 checkpoint（第 50–62、109–118 行）。模型构造在
`pu_common.py` 第 244–258 行，调用 `CrystalGraphConvNet` 的参数为
`atom_fea_len=64, n_conv=3, h_fea_len=128, n_h=1`。

`04_predict_clscore.py` 第 2–6、51–69 行定义了全池分数：对结构没有被抽入某
个 bag 的模型概率取平均，即

\[
  \mathrm{CLscore}_A(x)=
  \operatorname{mean}_{b:x\notin\mathrm{bag}_b}P_b(y=1\mid x).
\]

这就是 OOB 全池排序分数；OOB 不是“独立测试集”的同义词。

### B：MatterSim-1M-MLP-PU OOB

`07_embed_pu_head.py` 第 2–23 行说明 B 使用冻结的 MatterSim-v1.0.0-1M
编码器和小型 MLP 头，不微调势函数；第 282–287 行给出头部结构
`128 → 256 → 256 → 2`（SiLU、Dropout、LogSoftmax）。第 301–325 行显示
训练/验证行沿用同一 bag 划分，并以验证 ROC-AUC 选择最佳头；第 329–357 行
用相同的 bag-membership 掩码写出 `clscore_b_all.csv`。

`11_compare_scorers.py` 第 4–13 行将 A/B 描述为不同结构归纳偏置的两个评分器，
并指出二者共享 OOB 掩码。共享掩码支持逐结构配对比较和共识筛选，但不等于
两个分数已完成概率校准。

B 的 MatterSim 预处理会跳过少量无序、超大晶胞或近重合原子结构（实现见
`07_embed_pu_head.py` 第 211–230 行）。因此当前全池文件的覆盖并非完全相同：
`clscore_all.csv` 有 8,109,897 个未标注结构，`clscore_b_all.csv` 有
8,108,676 个，B 少 1,221 个。对 A/B 做逐结构比较时应先取共同 ID，不能把缺失
行当作低分或负例。

## 划分协议与可复核计数

`02_split_bagging.py` 第 2–13 行和第 38–56 行规定：20% 实验正例固定为各袋
共同的验证正例；每袋从未标注池抽取与正例等量的伪负例，再取其中 20% 作为该
袋验证伪负例，其余用于训练；每袋未被抽中的未标注结构才进入该袋 OOB 评分。

服务器重算生成的 `remote/protocol_audit.json` 给出本次快照的精确计数：

- 池共 8,208,887 行，其中实验正例 98,990 行、未标注行 8,109,897 行；
- 50 个 bag，每袋验证 39,596 行（19,798 正例 + 19,798 伪负例），训练
  158,384 行；
- 固定正例验证集在 50 袋间完全相同，训练/验证交集为 0；
- 审计明确写入 `independent_test_available: false`，原因是没有真实负例或
  untouched test 文件。

逐袋日志原文及行号索引保存在 `remote/log_line_provenance.tsv`。A 日志是
`/data1/home/hzxy10/csllm/logs/train_200535_1.out`、

## 图和表的含义

`figure_cgcnn_pu_validation_performance.*` 与
`figure_mattersim_1m_mlp_pu_validation_performance.*` 分别展示 50 个 bag 的
best validation ROC-AUC 分布（PNG、PDF、SVG 三种格式）。图中明确写出：

1. 标签为实验正例与抽样伪负例；
2. 数值是 validation ROC-AUC，而不是 independent-test ROC-AUC；
3. OOB 只表示全池评分时的 bag 外平均。

逐袋原始数值在 `per_bag_validation_auc.csv`，机器可读汇总在
`model_summary.json`，文件哈希和来源脚本在 `manifest.json`。优化后的 B 输出
保存在 `raw_B_opt/`；标准分类图（每个模型一行，左 ROC/AUC、右 threshold=0.5
混淆矩阵）见 `standard_roc_confusion/pu_models_roc_auc_confusion.pdf`。混淆矩阵
数字是逐袋平均计数，格内百分比按验证标签行归一化。

原管线 README（`script/pu_screening_v2/README.md` 第 42–48 行）写成 A
`0.9766 ± 0.0016`、B `0.9466 ± 0.0022`。这两个 ± 数值分别等于逐袋最小–最大
范围的一半（A 为 0.0016，B 为 0.00215，四舍五入为 0.0022），不是逐袋样本
标准差。本包同时给出明确标注为 `SD` 的样本标准差，避免混用两种摘要口径。

## 是否应该把 A、B 取平均

不应把未经校准的原始 `CLscore_A` 和 `CLscore_B` 做算术平均后称为新的
“合成概率”或“综合准确分数”。虽然二者都落在 0–1 区间并共享 OOB 掩码，A 是
CGCNN 分类头输出，B 是 MatterSim 表征上的另一个 MLP 分类头；PU 伪负标签、
正例比例、表示尺度和校准误差都可能不同。当前证据只支持：

- 分别报告 A 与 B 的排序和验证表现；
- 用两个低分尾部的交集作为保守共识（`08_consensus_negatives.py` 第 105–115
  行）；或
- 先在同一、真正独立且带可靠标签的数据上做校准/分位数变换，再定义有明确
  权重的组合分数。

现有脚本在 rank mode 中用 `CLscore_A + CLscore_B` 排序候选
（第 9、133–138 行）。这应被描述为工程上的 rank aggregator，而不是由物理
化学或概率模型推导出的平均值。

## 重算状态

早期作业 209577 因 MatterSim embedding 的重复解压实现而停止。修复为每个 shard
只 materialize 一次 `emb.npy` 后，优化作业 209663 在 1 分 26 秒内完成 97 个
shard 和 50 个 bag 的验证重算；`raw_B_opt/` 保留了五个紧凑输出文件及其哈希。
该修复只改变计算路径，不改变 split、模型头或标签协议。没有独立 test split，
所以本报告仍不把这些结果称为测试集性能。
