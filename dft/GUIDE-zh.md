# PRIS 第一性原理验证（E1–E4）说明

这份文档讲三件事：**为什么要做这四个计算**、**每个计算具体算什么**、**算完之后怎么把数据提出来**。

操作细节（怎么投、怎么续跑、赝势怎么办）在 `README.md`；连接超算和绕过本机代理在 `CONNECT-zh.md`；预测、判据和失败处理在 `PREREG-DFT.md`，那份文件在投第一个作业之前就已冻结并打了 git tag。

---

## 一、背景：为什么要做这批计算

论文的核心主张是"结构合理性是一层独立的判断，应当排在热力学稳定性、动力学稳定性和合成性之前"。PRIS 本身不依赖任何模型——八条法则只用形式电荷、离子半径和对称性。但**用来验证它、和它作对比的每一把尺子，目前都是学出来的**：

| 论文中的证据 | 现在的来源 | 审稿人会问 |
|---|---|---|
| 弛豫释放能量（图 5c,d：0.001 / 0.22 / 6.05 eV per atom） | MatterSim | ML 势在"不合理结构"上正处于分布外，凭什么可信 |
| E_hull 对比（72.0%） | MatterSim | 同上 |
| 逆向设计的 140 个高性质候选、67.3% 队列削减 | UMA 代理 | 体模量根本没算过 |
| 声子（35.6%、41.7%、4,271） | MP 已发表数据 | 那是筛过的数据库结构，不是生成结构 |
| D1 阈值 0.735 的物理依据（图 3c） | Born–Mayer 模型势 | 这是玩具模型，不是第一性原理 |
| 反例 2：GNoME 人工有序 | 换标签的 merge 统计 | 这是统计论证，不是热力学论证 |

一篇主张"第一性验证要有次序"的论文，自己一次第一性计算都没做。这是投 NCS 之上任何刊物的必问项。这四个计算各换掉其中一把尺子。

另外两点值得先说清楚：

**这批计算可能推翻论文里的数字。** 尤其是 E4——如果被 PSS 剔除的 61 个候选里真有 DFT 确认的高模量结构，"140/140 全保留"这个说法就不成立。正因为如此，选样规则、估计量和阈值必须在算之前写死。`PREREG-DFT.md` 就是干这个的。

**这是一条全新的证据链。** 记忆里那两条 2026-08-14 的密封求值已经用掉了，本次不碰它们，也不占用 lockbox 的剩余开封次数。E1/E2/E3 的实验结构一律取自 discovery 划分，held-out 保持干净。

## 二、内容：五个包分别算什么

四个实验，其中 E1 带一个对照包 E1b。胞都很小，最大 20 原子；617 个 stage-A 任务合计 6,861 个原子。

### E1 — 接触比 ρ_c 是不是一个可迁移的坐标（20 任务 / 340 次单点）

**要回答的质疑**：D1 把接触距离除以离子半径和，声称这样一个阈值就能跨化学体系通用；固定成埃的截断做不到这一点（论文 2.2 节的原话）。第一性原理支持这个说法吗？

**怎么算**：20 个 discovery 划分的实验母体（≤12 原子，O/S/F/Cl/N 各 4 个），每个沿 ρ_c ∈ [0.60, 1.40]、步长 0.05 共 17 点做**刚性各向同性缩放**。刚性是关键——PRIS 看到的就是提交进来的坐标，不做内部弛豫。只做静态单点，k 网格固定在最压缩那一点的密度，整条曲线没有网格跳变。

**估计量**：对每个化合物，`ρ*` 是压缩过程中能量代价首次达到 0.1 eV per atom 的接触比，`d* = ρ* × (r_cat + r_an)` 是同一个交叉点换算成埃。离散度用四分位距除以中位数。

**预测**：20 个化合物上 `ρ*` 的相对离散度至少比 `d*` 小 1.5 倍；且 `ρ*` 的中位数落在 [0.70, 1.00]，也就是把 D1 的两条下界夹在中间。若不成立，接触比并不比裸距离更可迁移，2.2 节"除以半径和"的第一性依据就不存在。

**为什么不用"下界处能量高于 0.5 eV per atom"**：那个说法不可能失败——ρ_c = 0.735 意味着体积压到 40%，任何化合物都要几个 eV per atom。而且在那个压缩程度上，最短接触只有 PAW 截断半径和的 0.66–0.94 倍（中位 0.77），冻结芯近似的误差恰好偏排斥，方向和预测一致。换成交叉点之后，主估计量落在 ρ_c ≈ 0.9 附近，PAW 球刚刚接触，结论不再依赖最压缩的那一端。0.735 / 0.804 / 1.05 处的超出量仍然照报，只是旁边附上该点的重叠比。

**这是最便宜的一个**，几个小时就能出结果，建议第一批只投它，顺便验证集群上的 VASP 调用、模块名和赝势路径都对。

### E1b — 硬赝势对照（8 任务 / 136 次单点）

**要回答的质疑**：压缩把原子推进彼此的 PAW 芯半径以内，那里冻结芯最不可靠，而且误差偏排斥——正好朝着 E1 想证明的方向。

**怎么算**：从 E1 的 20 个化合物里，按几何量（在 D1 下界处最短接触相对 PAW 半径和的比值）挑最紧的 8 个，换成小芯的硬赝势（O_h、F_h、N_h、S_h、Cl_h、B_h、C_h、P_h、H_h、Ga_h、Ge_h）重算，截断能随之提到 910–1005 eV。胞、网格、k 点规则全部不变，只有赝势不同——`verify.py` 会逐字节比对 E1b 与 E1 的 POSCAR 来确认这一点。

**预测**：硬赝势让 ρ_c = 0.735 处的超出能量变化小于 25%。若变化更大，压缩端就是冻结芯的假象，E1 全部改用硬赝势的数字。

### E2 — GNoME 的低对称性过量在热力学上是真的吗（128 任务 / 256 次）

**要回答的质疑**：论文把 GNoME 的低对称性过量部分归因于"化学相似元素的人工有序"，证据是合并标签之后对称性升高。那是统计论证。DFT 可以把它变成热力学论证：如果有序是人工的，同组成的其他排布应当近乎简并，那么在任何能合成的温度下它都是固溶体，而不是一个新化合物。

**怎么算**：24 个 D7 失败、含可合并相似元素对的 GNoME 条目（原胞 ≤20 原子，合并类 ≤10 个位点，对称不等价排布数在 2–12 之间），**每个条目的全部排布都算，一个不抽样**——要么穷举要么排除，这样"最低能量排布"不会因为抽样而被高估。对称不等价性由未着色母体的对称操作作用在位点指派上的轨道决定。10 个实验对照按同样的结构规则筛，限定在 RE 类（与 GNoME 集合中占主导的类匹配）。

**估计量**：有序能 `ΔE_i = E(发布的排布) − min_j E(排布 j)`（eV per atom，全胞弛豫后）；无序温度 `T_od = ΔE / (k_B · ΔS)`，`ΔS = −Σ x_a ln x_a` 为每个混合位点的构型熵。

**预测**：24 个 GNoME 条目的 `T_od` 中位数低于 300 K，10 个对照的中位数高于 1000 K；至少 60% 的 GNoME 条目低于 300 K，至多 20% 的对照低于 300 K。

**已声明的局限**：10 个对照里有 9 个属于 YbREX₃ 这一个结构家族。含两个同类元素且真实有序的化合物本来就少，这本身就是论点的一部分，但对照集不够多样，会照实写出来。

### E3 — 那五类受控破坏，在 DFT 看来也是破坏吗（200 任务 / 600 次）

**要回答的质疑**：五类破坏的严重程度目前由 MatterSim 标定，而 ML 势恰恰在这类结构上最不可靠。S5（阴阳离子互换）是最尖锐的情形：它不动任何一个坐标，一个以局部几何为输入的势可能根本看不见它。

**怎么算**：30 个 discovery 划分的实验母体（≤16 位点，且 `src/make_negatives.py` 的五个算子全部适用），各带五个破坏变体，另加 20 个未修改的 GNoME 母体，共 200 个胞。母体必须有序、最短接触 ≥1.0 Å，且六个胞里任何一个跌破 0.9 Å 就整组丢弃——DFT 在那种胞上算不出有意义的结果。每个胞先**固定晶胞只弛豫离子**（`ISIF=2`），再放开晶胞（`ISIF=3`），最后静态。

固定晶胞那一步是有意为之：论文图 5c,d 的 MatterSim 弛豫就是冻结晶胞的（fmax < 0.05 eV/Å、上限 200 步），两边必须在同一组自由度上比较才有意义。这一点是在写提数脚本时发现的，已按预注册的修订流程记录为 Amendment 1。

破坏用的随机数由 `sha256("E3|<source_id>")` 播种，而不是 Python 那个每进程加盐的 `hash()`，所以变体可复现。

**还查出一件事**：当两个阳离子子晶格恰好差一个平移时，S2 交换出来的晶体就是原来那个平移过去的——什么都没破坏。30 个母体里有 1 个（ZrCoF₆）是这种情况，已经在生成器里筛掉，`verify.py` 也会检查不再有漏网的。这是论文自己那个 S2 算子的性质；这种胞会被算成"未检出的破坏"，只会让 PRIS 显得更差而不是更好，所以已发表的数字没有风险。

**估计量**：`ΔE_relax = E(首个离子步) − E(末个离子步)`，取固定晶胞那一阶段。

**预测**：200 个胞上 DFT 与 MatterSim 的秩相关（Spearman）不低于 0.7；S5 的 DFT `ΔE_relax` 中位数比未破坏母体高出至少 0.3 eV per atom；且 S5/母体的比值在 DFT 下大于在 MatterSim 下。

### E4 — 逆向设计的筛选经得起第一性原理吗（261 任务 / 522 次 + stage B 约 1,305 任务）

**要回答的质疑**：67.3% 的队列削减和"140 个高性质候选全部保留"，目前完全建立在 UMA 代理上。没有一个候选被弛豫过，没有一个体模量被第一性算过。

**怎么算**：PSS 剔除的全部 61 个（`synthesis_score` 低于冻结阈值 −0.6368790173149083）、UMA 判定 ≥400 GPa 的全部 140 个、以及从剩下 880 个里按 `sha256("E4|control")` 无放回抽的 60 个对照，共 261 个。

- **Stage A**：把每个胞完整弛豫（这正是论文里"DFT 验证队列"的含义）。
- **Stage B**：把弛豫后的胞固定在 0.94 / 0.97 / 1.00 / 1.03 / 1.06 五个体积因子上，各自弛豫离子和晶胞形状（`ISIF=4`），得到能量–体积曲线，三阶 Birch–Murnaghan 拟合给出体模量。

Stage B 的作业包在集群上由 `make_stage_b.py` 从 stage A 的结果生成——它只用标准库，不需要集群装 pymatgen。**k 网格会按弛豫后的胞重新推导**（取曲线上体积最小那一点，五个点共用），因为生成的胞弛豫后通常会缩小，沿用 stage A 的网格就采样不足了。

**预测**：61 个被剔除的候选里，DFT 体模量 ≥400 GPa 的至多 2 个；140 个优先候选里至少 70% 被 DFT 确认 ≥400 GPa；261 个上 UMA 与 DFT 体模量的 Pearson r 不低于 0.8。

## 三、算完之后怎么提数据

三步：**collect（集群上跑，只用标准库）→ mattersim_reference（本地，只为 E3）→ analyze（本地，出 RESULTS.md）**。

### 第 1 步：在集群上提取原始结果

```bash
cd ~/pris-dft
python3 collect.py                                  # 四个包一起
python3 collect.py --package E4_design --stage-b    # E4 的 stage B 单独提
```

`collect.py` 只读 VASP 实际写出来的东西，**不做任何科学判断**——拟合、对称性分析、预注册比较全都在 `analyze.py` 里。它只用标准库，没有 numpy 也没有 pymatgen，所以集群上一定跑得动。

每个包写出两个文件：

- `collected.json` —— 完整记录，含每个阶段的逐离子步能量、最终 CONTCAR 文本、收敛标志、机时
- `collected.csv` —— 扁平表，方便直接看

**每个任务都有一个 `status`**，未完成的不会被丢掉而是记下原因：

| status | 含义 | 后续 |
|---|---|---|
| `complete` | 所有阶段退出码 0，都拿到能量 | 进入分析 |
| `unconverged` | 某个弛豫撞上离子步上限但仍有能量 | 进入分析，但标记 |
| `failed` | 某个阶段退出码非 0，或没写出能量 | 排除，理由记入报告 |
| `incomplete` | 某个阶段根本没跑 | 排除，理由记入报告 |

`collected.csv` 的主要字段：

| 字段 | 含义 |
|---|---|
| `<stage>.energy_ev` / `.energy_ev_per_atom` | 该阶段末次离子步的 `energy(sigma->0)` |
| `<stage>.release_ev_per_atom` | 该阶段的（首步能量 − 末步能量）/ 原子数，即弛豫释放的能量 |
| `<stage>.volume_a3` | 该阶段结束时的胞体积 |
| `<stage>.n_ionic_steps` / `.converged` | 离子步数；VASP 自己是否报告"reached required accuracy" |
| `<stage>.elapsed_s` | 该阶段的墙钟时间（乘上核数就是机时） |

跑完会打印一行实测机时汇总，可以用来校准剩余批次的排队参数。

### 第 2 步：E3 的 MatterSim 参照（本地，需要 GPU）

E3 要和 MatterSim 比，所以得在**同样的胞**上按**同样的协议**跑一遍 MatterSim：

```bash
python dft/mattersim_reference.py
```

协议与论文图 5c,d 一致：MatterSim v1.0.0 **5M**、固定晶胞只动离子、fmax < 0.05 eV/Å、上限 200 步。写出 `E3_crosscheck/mattersim_reference.json`，`analyze.py` 按任务名与 DFT 结果配对。这一步不做，E3 的其他数字照常出，只是秩相关那一项会显示"MatterSim 参照缺失"。

### 第 3 步：本地分析，得到结论

把集群上的 `collected.json` 同步回来（不需要整棵树，`collected.json` 就够，除非要重看结构）：

```bash
rsync -am --include='*/' --include='collected.json' --include='collected.csv' --exclude='*' \
      user@cluster:~/pris-dft/ dft/
python dft/analyze.py                                      # 写出 dft/RESULTS.md
python dft/analyze.py --only E2                            # 单独跑一个
```

`analyze.py` 里的每一个估计量和阈值都是从 `PREREG-DFT.md` 抄过来的，脚本只负责执行，不负责决定。它输出 `RESULTS.md`，开头就是一张预测核对表：

```
| experiment | prediction | measured | met |
| E2 | GNoME median T_od below 300 K | 180 K | yes |
| E4 | at most 2 screened candidates reach 400 GPa | 5 | **no** |
```

同时写出可以直接画图的中间结果：

| 文件 | 内容 |
|---|---|
| `E1_rho_curve/curves.json` | 每个化合物的 ρ_c–能量曲线、`ρ*` 与 `d*`、在 0.735 / 0.804 / 1.05 处的超出量、极小值位置 |
| `E1b_paw_control/paw_shift.json` | 8 个化合物在标准与硬赝势下的超出量及相对差异 |
| `E2_ordering/ordering_energies.json` | 每个条目的有序能、构型熵、`T_od`、弛豫后的空间群和位点经济度 |
| `E4_design/bulk_moduli.json` | 每个候选的 DFT 体模量、V0、B′、拟合残差，以及配对的 UMA 值和 PSS |

E3 的逐变体中位数表直接写在 `RESULTS.md` 里。

**阈值不在网格点上怎么办**：D1 的 0.735 和 0.804 不是 0.05 网格的点，脚本用保形三次插值（PCHIP）从算出来的点上读，避免普通样条在陡峭排斥壁上过冲。上界 1.05 本身就是网格点，直接读。

### 提数链路已经验证过了

真实数据还要等几周，所以提数链路是用**合成的 VASP 输出**先验证的：

```bash
python dft/selftest.py
```

它复制真实的任务目录（元数据、阶段串接、选样记录全是真的），只把 OUTCAR 和 CONTCAR 换成已知答案的合成内容，然后跑通 `collect.py → make_stage_b.py → analyze.py`，并断言：E1 的曲线读数和 `ρ*` 落在解析值附近；E1b 与 E1 的相对差异等于注入的 10%；E2 从静态能量算出的有序能和 `T_od` 与手算一致；E3 的破坏表和秩相关成形；E4 的 Birch–Murnaghan 拟合把注入的体模量还原出来。

当前状态：**通过**，E4 两个候选的体模量还原误差 0.00%。

写这个自测的时候查出了 `analyze.py` 的一个真 bug——原来直接按网格键去取 0.735 处的能量，而 0.735 根本不在网格上，会抛 `KeyError`。真跑完再发现就要多绕一圈。

## 四、投递建议：分三批，每批都有检查点

不要一次把 617 个任务全丢上去。分批的意义不是省机时，是**让第一个错误只毁掉 28 个任务而不是 617 个**——集群上的模块名、赝势路径、分区名、并行方式，任何一个不对都会让整批作业以同一种方式失败。

### 投之前，在集群上先确认五件事

| 要确认的 | 怎么确认 | 不对的话改哪里 |
|---|---|---|
| 分区与账号 | `sinfo`、`sacctmgr show user $USER` | 每个 `submit.slurm` 顶部加 `#SBATCH --partition=...` / `--account=...` |
| VASP 怎么调 | `module avail vasp`；`which vasp_std` | `submit.slurm` 里的 `module load vasp/6.3.0` 和 `VASP_BIN` |
| 赝势库在哪 | `ls $VASP_PP_PATH/O/POTCAR` | `submit.slurm` 里的 `VASP_PP_PATH`；库不存在就按 `README.md` 打包上传 |
| 单节点核数 | `sinfo -o "%P %c"` | `#SBATCH --ntasks-per-node`（现在是 16 或 32） |
| 队列时限 | `sinfo -o "%P %l"` | `#SBATCH --time`（现在是 12–24 小时） |

赝势库确认完，在集群上再跑一次核验，让它对着**集群自己的**库检查哈希：

```bash
python3 verify.py --potcar-lib $VASP_PP_PATH --report /tmp/verify_cluster.md
```

哈希不一致不是小事——说明集群上的赝势和本地那套不是同一版，物理结果会不一样。要么换库，要么在集群上重新生成任务包。

### 第一批：E1 + E1b（28 任务，几小时）

```bash
cd ~/pris-dft/E1_rho_curve  && sbatch submit.slurm
cd ~/pris-dft/E1b_paw_control && sbatch submit.slurm
```

**为什么先投这两个**：最便宜、最快、结构最简单（只有静态单点，没有弛豫，没有阶段串接），而且它们把整条链路都走了一遍——赝势拼装、k 点、截断能、驱动脚本、收集脚本。E1b 还顺便验证了高截断能（910–1005 eV）在集群上跑得动。

**回来之后逐项看**：

```bash
python3 collect.py --package E1_rho_curve --package E1b_paw_control
```

### 失败了怎么办（预注册第 1.3 节，不能临时改）

- 某个阶段退出码非 0 → 该任务停在那里，后续阶段不跑。照实记录。
- **只有墙钟超时**允许重跑一次，用**一模一样的输入**、更长的 `--time`。重跑要记进日志。
- 除此之外不许换参数重试。换了 `ALGO`、降了 `EDIFF` 再跑通的那个数，和别的数就不是一回事了。
- 重跑之后仍不收敛 → 报告为未收敛，从估计量里排除，并写明原因和数量。
- 任务是**可断点续跑**的：已经退出码 0 的阶段会被跳过，超时后直接重投同一个 array 即可。
